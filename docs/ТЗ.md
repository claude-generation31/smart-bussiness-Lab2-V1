## 1. Мета
Розробити Telegram-бот підприємства на платформі n8n, який вітає нових користувачів, відповідає на натискання кнопок і дає стандартну відповідь на довільні повідомлення.

## 2. Вимоги методички та їх покриття

|---|---|---|
| В1 | Зареєструвати бота, ім’я відповідно до варіанту | BotFather: ім’я «Кав’ярня Coffee Lab», нікнейм @CoffeeLabHorbatiukBot |
| В2 | Привітання новим користувачам | Гілка Switch `/start` → повідомлення з Reply Keyboard |

## 3. Технічний стек
- Telegram Bot API (реєстрація через @BotFather);
- Node.js LTS (20.x або новіша) + npm;
- n8n (запуск через `npx n8n`), вузли: Telegram Trigger, Switch, Telegram → Send a text message;
- тунель для webhook: `--tunnel` n8n або `localhost.run` (резервний варіант).

## 5. Логіка та тексти відповідей

Маршрутизація — вузол **Switch**, Mode: **Rules**, для кожного правила: Value 1 = `{{ $json.message.text }}`, оператор **String → is equal to**, Value 2 = текст кнопки (точно, з урахуванням регістру, без емодзі). Chat ID в усіх Send Message: `{{ $('Telegram Trigger').item.json.message.chat.id }}` (або `{{$json["message"]["chat"]["id"]}}`, як у методичці).

| Вихід Switch | Умова | Дія |
|---|---|---|
| 0 | `/start` | Привітання + клавіатура |
| 1 | `Меню напоїв` | Відповідь п. 5.2 |
| 2 | `Контакти` | Відповідь п. 5.3 |
| 3 | `Акції` | Відповідь п. 5.4 |
| 4 | `Графік роботи` | Відповідь п. 5.5 |
| 5 (Fallback) | будь-який інший текст | Стандартна відповідь п. 5.6 |

## 10. Можливі проблеми
- **Бот мовчить** — workflow не Active або змінилась адреса тунелю: перезапустити n8n, перевірити `WEBHOOK_URL`, вимкнути і знову ввімкнути workflow.
- **Кнопка дає стандартну відповідь** — текст у Switch не збігається з текстом кнопки (пробіли, регістр, емодзі).
- **«Waiting for tunnel…»** — використати `localhost.run` (розділ 7, крок 3).
- **Помилка на стікері/фото** — у Switch увімкнути Options → Ignore Case / Loose Type Validation або залишити Fallback, який перехоплює порожній текст.
